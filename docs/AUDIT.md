# 交互与缺陷检查

检查日期：2026-11-01。基线为内置主题 1.2.0，本项目版本 1.3.0。

## 已修复

| 问题 | 影响与处理 | 验证 |
| --- | --- | --- |
| 标签栏固定对称边距、多个控件共享网格单元 | 窄分栏的标签与控件可用空间被挤压；恢复宿主 flex 排布与原生窗口按钮避让，放弃强制几何居中 | 240 / 320 / 480 / 960px 分栏、18 标签，检查控件边界、互不重叠及实际命中 |
| 普通弹窗底色有透明度，移除了模态遮罩 | 后方高密度文字透进弹窗，焦点层次变弱；改为实色弹窗，恢复宿主遮罩 | 深浅色下实色表面与遮罩；真实宿主基线截图也观察到透字，未在真实宿主部署新主题 |
| 笔记阅读层仅 18% 不透明 | 文字对比依赖壁纸；阅读面改为实色，原生玻璃保留在窗口外壳 | 深浅色计算样式；同组检查在旧版 CSS 的阅读面断言处失败 |
| 通用 is-translucent 类触发桌面透明规则 | 不支持的窗口仍可能得到透明面；仅普通 macOS 桌面窗口启用主题透明方案，其余实色兜底 | Windows / Linux 类、macOS 全屏类、独立设置窗口类模拟 |
| 减少透明度未覆盖搜索控件等表面 | 开启系统偏好后仍有透明按钮；补齐相关表面变量并降低兜底变量的选择器权重 | Chromium CDP 模拟媒体查询，检查工作区、搜索与弹窗不透明 |
| 目录装饰与交互状态、RTL 方向的兼容 | 原生选中、拖动、重命名、菜单与焦点状态避开装饰，目录标记使用方向变量 | 六种文件树状态、RTL 背景标记方向 |
| 禁用按钮仍可获得主题悬停 / 按压反馈 | 排除 disabled、is-disabled 与 aria-disabled 状态，并同步校正减少动态效果规则的权重 | 减少动态效果过渡时长为零、按压无缩放；禁用按钮验证 |
| 移动端工具按钮偏小 | 增大工具按钮触控区域，保留宿主手机端隐藏标签栏 | 手机类模拟下标签栏隐藏、工具按钮最小 40px |
| 特殊可访问性模式 | 补充强制颜色下的活动标签与焦点轮廓，保留用户强调色 | 强制颜色焦点、搜索焦点颜色、键盘焦点样式 |

固定设置标题使用统一的实色底，避免滚动文字穿过标题。保留宿主堆叠标签间距；没有新增脚本、运行时设置、网络请求、整页遮罩、body 模糊或常驻动画。

## 已完成的验证及边界

- `npm test`：清单 / 版本一致性、严格 CSS 解析、离线资源、无插件依赖、允许用户 snippet 覆盖、无常驻 backdrop-filter。
- `npm run test:ui`：使用本机宿主 1.14.5 的 app.css 和独立虚构 DOM，在 Chromium 中验证计算样式、控件命中、设置滚动与状态切换。本次 70 项检查通过。
- 深浅色浏览器模拟图经视觉检查，输出到 `output/playwright/`。这些图是**模拟页面**，不是应用实拍，也不能作为社区商店截图。
- 浏览器验证不运行宿主 JavaScript，不能证明标签拖拽 / 重排、文件移动 / 重命名、窗口拖动 / 缩放、原生毛玻璃材质或插件兼容性已经真机验收。
- 没有修改或构建原插件。独立主题部署脚本只更新主题的两个运行文件，保留备份，不修改外观偏好。
- 工程改造后，模块化源码经压缩构建后重复运行浏览器检查；另有 12 项工程测试覆盖可复现打包、备份、回滚、外部编辑、版本保护、锁与路径保护。实际部署到本机已安装的主题目录，部署后的两文件与 dist 逐字节一致，旧版本备份校验通过；宿主 appearance.json 与插件 data.json 的哈希均未改变。
- 本次部署后的原生界面截图调用受 ScreenCaptureKit `-3811` 错误阻断，因此不将文件部署核对或浏览器模拟结果表述为原生视觉验收。

## 上架前仍需验收

1. **macOS 实际宿主**：无社区插件的空白演示库，浅色 / 深色，半透明窗口开 / 关，全屏，左右栏开 / 关，窄分栏与大量标签，堆叠标签、拖拽重排、重命名 / 多选 / 文件移动，重启后外观。
2. **弹层**：命令面板、搜索建议、快速切换、设置页滚动、独立设置窗口、右键菜单及图谱 / PDF / Canvas；确认遮罩关闭方式与键盘焦点符合宿主行为。
3. **系统与设备**：最低支持版本 1.14.0；当前只用 1.14.5 的 CSS 验证。Windows / Linux、iOS / Android 真机、触摸操作、系统原生减少透明度、不同缩放比例与 RTL 界面。
4. **驾驶舱可选兼容**：搜索、番茄钟浮层和日历滚动；本项目没有新增合成层，但这三处仍值得在真实插件中回归。
5. **发布材料**：真实应用的演示截图、GitHub 新仓库与 Release，社区名称可用性和自动审核结果。

## 后续优化建议

- 完成真实设备矩阵后再决定是否正式宣称移动端支持；现阶段提供保守 CSS 兜底。
- 如用户希望恢复居中页签，可在后续版本考虑可选样式，先测试窄分栏、窗口按钮、RTL 与多页签，再引入；避免再次强制修改宿主核心布局。
- 暂不加入 Style Settings 依赖；当前由原生强调色、深浅色与系统可访问性偏好控制。若之后确需更多配置，可作为可选增强，保持无插件可用。
- 新宿主版本优先检查文件树、标签栏和设置页结构选择器，逐步减少对具体 DOM 层级的依赖。
